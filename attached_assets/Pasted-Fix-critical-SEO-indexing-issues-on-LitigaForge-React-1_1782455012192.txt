Fix critical SEO/indexing issues on LitigaForge (React 19 + Vite frontend, FastAPI backend). Google Search Console data shows:
- Site is splitting ranking signal across 3 URL variants: https://litigaforge.com/, http://litigaforge.com/, https://www.litigaforge.com/ — all indexed separately
- Only ~10 of 42+ blog posts are getting any search impressions at all; the rest appear uncrawled/unindexed
- 96% of impressions show as "(unknown)" query, suggesting weak/thin content signals
- Zero clicks across all blog posts despite some ranking position 3-5

Do the following, in order:

1. DOMAIN CANONICALIZATION
   - Force a single canonical domain: https://litigaforge.com (no www, no http)
   - Add a 301 redirect at the server/edge level: http:// → https://, and www.litigaforge.com → litigaforge.com
   - Add <link rel="canonical" href="https://litigaforge.com{path}"> dynamically on every page, matching the actual current URL path

     a) Prerendering at build time for all known routes (blog posts, judgment pages, static pages) using a tool like vite-plugin-ssr, vite-react-ssg, or a custom prerender script that renders each route's HTML and serves static files to crawlers
     b) OR dynamic SSR via the FastAPI backend for bot user-agents, returning fully rendered HTML
   - This must apply to ALL blog post routes (/blog/*), judgment pages (/judgments/*), and core pages — not just the homepage

3. META TAGS PER PAGE
   - Each page must have a unique <title> and <meta name="description"> reflecting actual page content (not the default homepage tags duplicated everywhere)
