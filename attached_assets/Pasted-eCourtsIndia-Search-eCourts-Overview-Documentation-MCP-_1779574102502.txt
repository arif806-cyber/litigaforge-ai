Authentication
All API requests (except Court Structure) require Bearer token authentication. Include your API token in the Authorization header.

Bearer Token Format
Authorization: Bearer eci_live_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
Prefix: eci_live_
Length: 41 characters
Format: Alphanumeric
Response Format
All successful responses follow this structure:

JSON

{
  "data": { ... },
  "meta": {
    "requestId": "req_abc123xyz"
  }
}
Security Warning
Keep your API token confidential. Do not expose it in client-side code.
Never commit tokens to version control or share in public repositories.
If compromised, contact us immediately to regenerate your token.

Core Concepts
Key concepts for working with the eCourts API.

CNR (Case Number Record)
A CNR is the unique 16-character identifier for every case in the eCourts system.

Pattern: [A-Z]{4}\d{12}
Components: [Court Code: 4 letters][Case Number: 6 digits][Filing Year: 4 digits]
DLHC010351552024 → Delhi HC, case 035155, filed 2024
HCBM050012342023 → Bombay HC (Kolhapur), case 001234, filed 2023
Court Hierarchy
text

Supreme Court of India (SC)
├── High Courts (37 across states/UTs)
│   ├── Original Jurisdiction
│   └── Appellate Jurisdiction
├── District Courts
├── National Company Law Tribunal (NCLT)
├── National Company Law Appellate Tribunal (NCLAT)
└── Specialized Tribunals
Cause List
A cause list is the daily schedule of cases to be heard in a specific courtroom. Each entry shows the case number, parties, assigned judge, expected hearing time, and case status. Use the Cause List Search endpoint to query schedules across courts.

Credit-Based Pricing
Most authenticated endpoints consume credits per request. Court structure endpoints and enum reference are free. Check your account balance and see the pricing page for details.

GET
/api/partner/case/{cnr}/order/{filename}
Order Download (PDF)
Get order document metadata and download information. PDFs are certified true copies from the eCourts system.

Parameters
Parameter	Type	Required	Description
cnr	path	Yes	Case Number Record
e.g. DLHC010001232024
filename	path	Yes	Order filename from judgmentOrders[].orderUrl
e.g. order-1.pdf
How to get the filename:
Call GET /api/partner/case/{cnr} to get case details.
Look in courtCaseData.judgmentOrders[] or courtCaseData.interimOrders[] for orderUrl values.
Example Request
cURL

curl -X GET "https://webapi.ecourtsindia.com/api/partner/case/DLHC010001232024/order/order-1.pdf" \
  -H "Authorization: Bearer eci_live_your_token_here"

GET
/api/partner/case/{cnr}/order-ai/{filename}
Order + AI Summary
Get extracted text and AI analysis for a court order: summary, key points, outcome, relief granted, and legal provisions cited. Generated on-demand on first access, cached thereafter.

Parameters
Parameter	Type	Required	Description
cnr	path	Yes	Case Number Record
filename	path	Yes	Order filename from judgmentOrders[].orderUrl
May take 10-60 seconds. This endpoint performs on-demand processing from government court servers on first access. If aiAnalysis is null, retry up to 3 times with 15-30 second waits. Subsequent accesses are cached.
Example Request
cURL

curl -X GET "https://webapi.ecourtsindia.com/api/partner/case/DLHC010001232024/order-ai/order-1.pdf" \
  -H "Authorization: Bearer eci_live_your_token_here"

Important Notes & Gotchas
Common pitfalls and things to watch out for when using the API.

Wrong Enum Codes = Silent Empty Results
If you pass wrong enum codes to search, you get 0 results with no error. Always verify codes using the Enum Reference endpoint or the enum tables below before searching.

cURL

# WRONG — returns 0 results silently
GET /api/partner/search?caseTypes=BAIL_APP

# CORRECT — use validated code
GET /api/partner/search?caseTypes=BA
Order AI Analysis is On-Demand (10-60s)
The order-ai endpoint performs on-demand processing from government court servers on first access. Expect 10-60 second latency. If aiAnalysis is null, retry up to 3 times with 15-30s waits. Fall back to order-md for raw text if needed.

Order Markdown Can Take Up to 300 Seconds
The PDF conversion pipeline is slow. Full order text is already available in Case Detail response under files[].markdownContent. Only use the order-md endpoint when you need the watermarked PDF for official submission.

High Court Codes Need Bench Suffix
High Court codes must include bench suffix for searching. DLHC returns 0 results — use DLHC01.

cURL

# WRONG — base code, returns 0 results
GET /api/partner/search?courtCodes=DLHC

# CORRECT — full code with bench suffix
GET /api/partner/search?courtCodes=DLHC01
NCLT Codes Need Trailing '0'
NCLT bench codes must end with 0 for searching.

cURL

# WRONG: GET /api/partner/search?courtCodes=NCLTDL
# CORRECT:
GET /api/partner/search?courtCodes=NCLTDL0
SC = India (Supreme Court)
In state codes, SC represents the Supreme Court of India, not a state. It appears in the states list as "state": "SC", "stateName": "India".

Cause List Uses Offset Pagination
Cause list search uses offset-based pagination, not page numbers. To get page 2 with limit=20: offset=20. Next page: offset = previous_offset + limit.

courtNo vs court in Cause Lists
In cause list results, courtNo is the room number and court is the internal identifier. These are different fields — don't confuse them when filtering.

All Dates Use YYYY-MM-DD Format
All date parameters and response fields use YYYY-MM-DD format. Datetime fields include timezone suffix (Z).

Case Category is Free-Form in Case Data
Case category enum codes are search filters only. The actual caseCategory field in case data is free-form court text (e.g., "Constitutional Writ"), not a value from the enum.

Acts/Sections Filter — Exact Match, Very Limited Coverage
The actsAndSections filter requires the exact stored-text format and has very limited index coverage. Most cases do NOT have this field populated. The filter also doesn't appear in activeFilters.

cURL

# WRONG — abbreviation, returns 0:
GET /api/partner/search?actsAndSections=IPC+302

# TECHNICALLY CORRECT format — but still returns 0 for most courts:
GET /api/partner/search?actsAndSections=INDIAN+PENAL+CODE+-+302

# RECOMMENDED — use full-text query instead (432K+ results):
GET /api/partner/search?query=IPC+302
For general act/section searching, use the query parameter instead. The actsAndSections filter is only reliable when you know the exact stored text format and the case has this field populated.

Refresh is Idempotent Within 15 Seconds
Calling refresh multiple times within 15 seconds is safe — no duplicates are created. Wait 5-10 seconds after queuing before fetching updated case details.

Best Practices
Cache responses: Store case details locally to reduce API calls and costs.
Batch operations: Use search to find multiple cases instead of individual lookups.
Handle rate limits: Implement exponential backoff for 429 responses.
Use refresh sparingly: Only request case refresh when you need the latest data.
Store request IDs: Log requestId from responses for support inquiries.
